# unified-ops AI 学习映射 V1.0

本文依据上游基线 `f84c04268794ef94f8949808bbc14ab8636763a0` 的章节 README 与 notebook 源文本。所有 unified-ops 能力为规划映射，当前实现状态均为 `NOT_STARTED`。本次未访问 unified-ops 源码，已有采集和规则能力的接口契约待后续读取项目核验。

## 目标工作流

生产问题/告警 → 采集模块 → 规则验收 → 知识库检索 → 本地 DeepSeek 分析 → 结构化诊断报告 → 人工审核 → 必要时 GPT 深度分析 → Codex 修复 / Gitee 版本管理。

这条流程来自个人项目目标。教程提供其中的调用、提示、多轮记录和评测思路。采集器、规则引擎、RAG 管线、修复流程及 Gitee 集成需要在后续项目中设计和验证。

适用程度分为“高”“中”“低”“缺完整教程”。高适用表示内容有借鉴价值，仍需适配和验证。

### 四类结果的含义

以下字段为个人 PoC 设计，字段名和验证规则尚待实践。

| 类别 | 应记录的信息 | 后续校验 |
| --- | --- | --- |
| FACT | 采集到的指标、时间、单位、字段路径和证据 ID | 可回溯到输入，数值与单位一致 |
| INFERENCE | 基于证据的推断、支持它的事实、仍可成立的其他解释 | 引用确实支持该判断，避免将相关性直接定为原因 |
| UNKNOWN | 缺失数据、冲突证据、无法确认的事项与补采需求 | 缺失字段保持未知，不默认补零 |
| RECOMMENDATION | 建议动作、依据、预期影响和是否需要人工审批 | 对照运维规范审核，修复执行经过人工确认 |

报告应给出简明判断依据和证据引用。模型生成的解释和自评分都需要与输入、规范及人工标注交叉验证。多次生成结论一致只能作为稳定性观察。

### 后续学习样本与验收方向

使用合成数据覆盖正常缓存占用、匿名内存增长、共享内存、Swap 压力、容器限制、权限缺失、陈旧样本及冲突检索结果。后续指标至少包括 JSON 可解析率、事实准确率、引用正确率、检索命中情况、未知项识别率、风险建议误判和人工复核结果。

RSS/PSS、MemAvailable、Swap、进程与 cgroup 视图的定义和统计范围需要另查对应系统文档。规则阈值要记录来源及适用条件，不能由模型临时编造。

第 10 章终止关键系统进程的案例适合作为风险评审样本。此 PoC 初期目标是形成诊断报告和补采建议，执行能力需要后续单独设计与验证。

## 与 GPT、Codex 和版本管理衔接

本地模型报告先由人工复核。需要 GPT 深度分析时，另行确认允许外发的脱敏证据与问题范围。Codex 接收具体修复任务、证据和验收标准，在测试环境验证，再按 unified-ops 的 Gitee 工作流提交。模型输出中的命令仅作待审核建议。

- Hugging Face、GitHub、模型 API、视频及下载站的国内网络连通性未实测。镜像下载也需做文件完整性与版本核对。
- 第 9、10 章部分课件链接与当前目录不符，已在 [学习路线](STUDY_ROADMAP.md) 记录。PDF 正文及站外教程未进行完整内容核验。
